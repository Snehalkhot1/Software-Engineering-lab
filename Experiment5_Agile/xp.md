
# Part C: Extreme Programming (XP) Implementation

## Project
Student Management System

## XP Practices

### 1. Pair Programming
Student A:
- Writes the code.

Student B:
- Reviews the code and identifies errors.

The students switch roles every 30 minutes.

### 2. Test-Driven Development (TDD)
1. Write tests for registration and login.
2. Run tests and check the result.
3. Implement the required functions in main.py.
4. Run tests again.
5. Fix defects and repeat until tests pass.

### 3. Continuous Integration
- Save changes frequently.
- Run automated tests after changes.
- Fix failed tests before integrating changes.
- Use Git to track versions if available.

### 4. Refactoring
- Improve code readability.
- Remove repeated code when possible.
- Keep function names clear.
- Run tests after changes to check that behavior is unchanged.

### 5. Small Releases
Implement and test registration and login first.
Then add student operations and test them.

## XP Result
Automated tests verify important functions, while frequent
testing and code reviews help detect defects early.
